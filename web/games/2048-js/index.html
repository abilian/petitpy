What lives where

Compared to Snake's main.py: the slide-and-merge logic stays in main.py as ordinary Python, since that part never touched the bridge. What moves into nanopy.py (81 code-lines, paid once): the _g / _set_text / _set_status wrappers, the 16-bit LCG, the ctx.set("fillStyle", X) property-write idiom (now canvas["fillStyle"] = X), the js.window.set("__gFoo", on_foo) dispatch registrations (now @on_key("ArrowLeft")), and the localStorage try/except dance (now storage.get_int / set_int).

Aspirational shape of main.py after Tier 2 #5 (__setattr__ on nano, deferred from v0.6.0): canvas["fillStyle"] = BG becomes canvas.fillStyle = BG. The helper rewrites trivially; the game code doesn't.
