#   - `make check-full` (when wired) runs tools/full_gate.py.

#   - The list only ever SHRINKS without an ADR-justified addition.

# --- DEQUE CPYTHON-COMPAT DIVERGENCE (2) --------------------------------
# Same deque-shim story that's tracked under corpus/wasm-known-fails.txt.
# petitpy-lib/collections.py ships a CPython-compatible deque(iterable)
# — deque(()) works, no size arg required. Vendor MP's C-level deque is
# stricter (deque(iterable, maxlen) required; d[i] TypeErrors on slice).
# We chose CPython-compat because BFS / real-world algorithms use it.
# The strict-MP behavior is still reachable via `from ucollections
# import deque`. Both were fine under check-full pre-v0.7.1 because
# `from collections import deque` failed at import (no frozen-tiny in
# the check-full binary) → tests SKIPped; now that check-full carries
# the frozen set, the SKIP is gone and the tests reach the assertions.
deque_micropython
deque_slice

#  (src/modules/modbuiltins.zig): under full, a 1-byte non-ASCII str

#  would need both a lexer flip AND codepoint-aware bytes_subscr;
#  deferred. Closes ord("\xff") == 255 which is what CPython + vendor
#  give.)
